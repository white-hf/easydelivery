# Power Saver Map Browse PRD

## 背景

系统当前有 `PowerSaver` 和 `realtime` 两种模式。

- `realtime` 适合地图跟随、接近投递、实时导航辅助。
- `PowerSaver` 适合省电，但司机位置在地图上的更新可能超过 `8s` 才刷新一次。

在这种低频定位场景下，当前地图体验会出现一个问题：

- 地图上的蓝点位置不够及时。
- 司机仍然知道自己大概在哪条路、哪个街区。
- 但地图如果仍按原来的跟随和聚合逻辑展示，司机很难快速通过地图判断“我附近有哪些包裹、包裹号分别是什么”。

因此需要一个新的地图展示模式，让 `PowerSaver` 不再追求精确实时跟随，而是转向“低频定位下的范围浏览”。

## 产品目标

- 在 `PowerSaver` 模式下，为司机提供一个更适合低频定位的地图浏览模式。
- 让司机能在更大范围内看到附近包裹分布，并结合自己对当前位置的判断完成投递决策。
- 在该模式下，屏幕内包裹不应默认聚合成 cluster，司机应尽量直接看到包裹号。
- Android 和 iOS 行为保持一致。

## 非目标

- 不在 `PowerSaver` 下继续追求 `realtime` 级别的跟随体验。
- 不要求在所有密集区域都无上限显示全部包裹。
- 不要求第一版解决所有地图浏览、marker 排版、重叠冲突问题。
- 不替代现有 `realtime` 跟随模式。

## 用户故事

- 作为司机，当我使用 `PowerSaver` 时，即使地图定位更新较慢，我也希望看到我附近更大范围的包裹分布，并直接读到包裹号，这样我可以根据自己实际所在位置快速判断接下来要去哪里。

## 核心方案

新增一个 `PowerSaver Map Browse Mode`：

- 仅在 `PowerSaver` 模式下启用。
- 地图以“范围浏览”而不是“精确跟随”为主要目标。
- 默认展示更大范围地图，建议首版控制在 `2km - 3km` 量级。
- 该模式下不采用当前默认聚合展示。
- 但为了避免一屏 marker 过多，需要限制同屏可展示的最大包裹数量。

## 关键交互定义

### 1. 地图视野

- 默认视野应明显大于当前 `realtime` 驾驶跟随模式。
- 第一版建议目标范围为 `2km - 3km`。
- 非常稀疏区域可适度放大，但不建议第一版默认做到 `5km`。

### 2. 聚合行为

- 在 `PowerSaver Map Browse Mode` 下，不使用当前默认 cluster 展示。
- 司机应尽量直接看到包裹号和大概分布位置。

### 3. 同屏包裹上限

- 为防止密集区域地图过乱，需要限制同屏 marker 数量。
- 第一版建议上限 `20 - 35` 个。
- 超出上限时，不显示全部包裹，而是按优先级筛选。

### 4. 包裹筛选优先级

同屏可见包裹建议按以下优先级筛选：

1. 当前 focus / 当前推荐链路相关包裹
2. 离司机最近的包裹
3. 屏幕中心附近包裹
4. 特殊包裹，如大件

### 5. Marker 样式

- `PowerSaver Map Browse Mode` 下 marker 应比当前跟随模式更轻。
- 优先显示短包裹号，减少视觉噪声。
- 当前焦点包裹应有更明显高亮。
- 大件保留特殊标识。

### 6. 相机行为

- 不再强调实时自动跟随。
- 位置更新时仅做低频、平滑的小幅 recenter。
- 用户手动拖图后，系统应更保守地恢复自动居中。
- 避免频繁 zoom in / zoom out。

## 适用场景

- 司机打开 `PowerSaver`，希望在省电的同时继续通过地图完成大方向判断。
- 司机处于普通街区、乡镇或低中密度区域，需要通过较大范围地图看清附近多个包裹号。
- 定位刷新较慢，但司机自己能判断当前所在道路位置。

## 不适用场景

- 强依赖实时接近判断的接近投递场景。
- 需要 street-level 精确门牌定位的最终接近阶段。
- 市中心极密集区域若无筛选限制，直接全量无聚合会导致严重视觉噪声。

## 风险与防护

### 风险 1：屏幕内 marker 过多，地图变乱

防护：

- 增加同屏 marker 上限。
- 使用可见包裹筛选策略。
- marker 视觉样式轻量化。

### 风险 2：司机误以为 `PowerSaver` 仍应提供实时跟随

防护：

- 该模式在产品定义上明确为 browse mode，不是 realtime follow。
- UI 或内部文档中明确此模式目标是“更大范围浏览”。

### 风险 3：Android / iOS 行为逐渐不一致

防护：

- 用统一的模式定义和策略分层设计。
- 两端按照同一产品模型实现，而不是各自临时加条件分支。

## 实现范围

### Android

- 地图展示模式切换
- 相机 browse 行为
- cluster / marker 展示策略
- 包裹筛选策略

### iOS

- 地图展示模式切换
- 相机 browse 行为
- cluster / marker 展示策略
- 包裹筛选策略

## 验收标准

1. 开启 `PowerSaver` 后，地图进入新的 browse 展示模式，而不是继续沿用当前 realtime 跟随语义。
2. 第一版默认展示范围明显大于现有 realtime 驾驶跟随模式。
3. 在 browse 模式下，包裹不以当前默认 cluster 方式展示。
4. 同屏 marker 数量受控，地图不会因为密集区域完全不可读。
5. 司机能直接在地图上看到一组附近包裹号，而不是只能看到聚合点。
6. Android 和 iOS 在模式定义、同屏上限、筛选优先级和相机总体行为上保持一致。

## 当前结论

该需求不是“给 PowerSaver 做一个更差的 realtime 地图”，而是“给低频定位场景做一个正确的地图浏览模式”。
